# 切り抜き
ブラウザ内で位置指定による画像切り抜きを行う静的Webアプリ。複数画像を読み込み、写真上で残したいものをなぞると、線全体を一つの選択として追加する。クリックによる選択もできる。マウス・タッチ・ペンに対応し、指を離すと切り抜きを開始する。「選択を直す」から、同じ対象に残す線・除く線を追加できる。一回の取り消しで一筆分を戻し、Escapeや操作の中断では描きかけを破棄する。元写真と仕上がりを常に並べ、選んだものは画像付きの一覧から個別に取り消し・修正できる。細かな範囲の候補や輪郭調整は「仕上がりを調整」にまとめた。元解像度の透過PNGと、完成した複数画像のZIP保存に対応する。

背景除去はIMG.LYのISNetを基本にする。画像ごとの前景マスクから、残す線が触れた対象を丸ごと選択する。同じ画像の選択追加では背景除去を再実行しない。ISNetが消した皿なども指定された場合のみ、SlimSAMで追加の領域を求め、ISNetが残した料理と合成する。SlimSAMだけで料理の内部が抜ける現象を減らす構成。除外指定が同じ前景に重なる場合はその領域をSlimSAMで調整する。

補助推論では線から均等に取った最大64点を評価に使う。モデルへ一括入力せず、候補が取りこぼした位置だけを追加する（最大8回・8点）。候補を残す／除く指定との一致でも評価し、線が触れていない分離領域を除く。接触した複数対象、透明物、低コントラストの輪郭などには限界がある。
## 外周からのマスク再構成
選択した領域は、最終段で一枚の輪郭マスクに再構成する。確率マスクをまとめ、長辺1024pxなら半径4pxのクロージング（膨張→収縮）で細い切れ目を補完した後、画像の外側から背景をフラッドフィルする。外側から到達できない領域を内側として塗り、複数の選択やモデルの境界に残った穴・半透明の隙間を埋める。元から存在した輪郭の半透明部分は外周で保持し、その後に輪郭のぼかしを適用する。
「除く」の点・線が触れた背景領域は穴埋めから保護する。線は始点と終点の間も画素単位で評価する。離れた対象の間の広い背景や外側につながる大きな凹みを一括で埋める凸包処理は行わない。画像端に接する対象も欠けないよう、形態学処理には余白を付ける。内部の穴を基本的に埋めるため、持ち手など透過させたい穴は「除く」で指定する。
完成画像は元写真にこの一枚のマスクを適用して生成する。切り抜き済み画像の貼り合わせや生成補完は使わず、補完した場所にも元画像の画素が入る。画面表示・透過PNG・一括ZIPで同じ最終マスクを使い、範囲のサムネイルにも同じ処理を適用する。
## 仕上がりの消しゴム
仕上がり画像をなぞった部分は、その場で透明になる。太さは表示上の直径8・16・32・64・96pxの5段階。線と太さは元画像の座標で保存し、画面サイズや余白の切り詰めに合わせて変換する。輪郭補完の後に直接アルファを削るため、内部の穴も埋め戻されず、推論は実行しない。透過PNGと一括ZIPにも同じ筆跡を適用する。
一筆ごとに既存の履歴へ保存し、仕上がり欄の戻すボタン・Ctrl/Cmd+Zで取り消せる。マウス・タッチ・ペンに対応する。Escape、入力のキャンセル、画像の切り替えでは描きかけだけを破棄する。元写真の比較表示中は消去しない。写真ごとに筆跡を保持する。
## GitHub Actionsでのデプロイ

1. ZIPを展開し、`kirinuki-studio/`の中身をGitHubリポジトリのルートへ配置する。`.github/`も含める。
2. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選ぶ。
3. `main`ブランチへpushする。既にpush済みなら **Actions → Deploy to GitHub Pages → Run workflow** で手動実行する。

`.github/workflows/deploy-pages.yml`がJavaScriptの構文、モデルキャッシュ、編集状態と透過PNG出力を検証し、`dist/`をGitHub Pagesへデプロイする。アプリ自体はビルド不要。Actions内ではテスト用にのみ`@napi-rs/canvas`を一時フォルダに取得する。既定ブランチが`main`以外の場合はworkflowの`branches`を変更する。完了後の公開URLはActionsの`github-pages`環境から開ける。

モデルとService WorkerのURLは配置先から解決するため、`https://<owner>.github.io/<repository>/`と独自ドメインの両方に対応する。キャッシュのキーも配置先とモデルリビジョンで分ける。

個人の写真およびデバッグ用画像はリポジトリ・配布物に含めない。

GitHub公式の手順: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## 実行
`dist/`をHTTPSで配信する。添付されたcoi-serviceworker v0.1.7を基に、モデル配信処理への分岐だけを追加した。初回はService Workerによる再読み込みが発生する。COOP/COEPでクロスオリジン分離し、ONNX RuntimeのWASMスレッド数を利用可能な論理コア数（最大8）に設定する。WebGPUを優先し、利用できない場合はWASMへ移行して画面に表示する。HTTPの非localhost環境ではService Workerを利用できない。

推論はメイン画面側で監視する。60秒間応答がない場合、または1試行が180秒に達した場合はWorkerを終了する。WebGPU優先→マルチスレッドWASM→単一スレッドWASMの順に、新しいWorkerで有限回だけ試し、失敗時はエラーと再試行ボタンを表示する。初期化失敗後の壊れたランタイムを再利用しない。通信が45秒止まったモデル取得は中断し、共有の待機状態を解除する。再読み込み時にはService Workerの更新も確認する。
## モデルとランタイム
主モデルはHugging Faceの`imgly/isnet-general-onnx`（モデルカードのライセンス: MIT）、固定リビジョン`440dea96dd4a3b06bbbf5abec3e26569dd7ec49f`の`onnx/model.onnx`（FP32）。176,149,806バイト。このファイルの全42区間をSHA-256で照合し、`@imgly/background-removal@1.7.0`公式`resources.json`の`/models/isnet`とバイト単位で一致することを確認した。記事の約40MBの量子化版とは容量が異なる。

npmライブラリ自体は組み込まず、同じ公開モデルを既存の推論・キャッシュ経路で実行する。入力はIMG.LYと同じ1024×1024への縦横独立リサイズ、RGB `(value - 128) / 256`。出力は確率マスクとして扱い、SAMのパディングやロジット処理と混同しない。

補助モデルは`Xenova/slimsam-77-uniform`（Apache-2.0）、固定リビジョン`5850ab45f587c112167512ffef949107115e26a0`、FP32。選択の補完が必要な場合だけ約39.84MBを取得する。作業用マスクの長辺は最大1024px。元画像は保持し、透過マスクを元の寸法に拡大してPNGにする。
Transformers.js 3.5.0と、その配布物に同梱されたONNX Runtime WebをjsDelivrから読み込む。WASMとJavaScriptのバージョンを混在させない。画像と点座標を外部へ送信する処理はなく、画像解析は専用Web Workerで行う。ZIP出力にはfflate 0.8.2をjsDelivrから読み込む。
## キャッシュと検証
Service WorkerがHugging Faceの公開resolve APIからモデルをストリーム受信し、50,000,000バイトを上限に分割して`kirinuki-model-parts-v2` Cache Storageへ保存する。ISNetは50MB×3と26,149,806バイトの計4チャンク。補助モデルは約23.28MBと16.56MBの各1チャンク。異なるモデルの同名ファイルが混ざらないよう、リポジトリ・リビジョン・ファイル名をキーに含める。画面はService Workerとのバージョン確認を済ませてから推論を開始する。

hash-wasm 4.12.0のxxHash64（seed 0）で、初回取得時とキャッシュからの読み込み時に全バイトを検証する。固定配布ファイルから得た期待値は、ISNet model.onnx: `5def2979ea4340f0`、SlimSAM vision_encoder.onnx: `66ab8e4a5a44439c`、prompt_encoder_mask_decoder.onnx: `cc11b9de008291cb`。サイズも一致を確認する。xxHashは破損検出用で、暗号学的な署名ではない。
検証成功後だけ完了manifestを書き込む。キャッシュが欠落・破損していれば当該モデルのチャンクを破棄して再取得する。ネットワークから取得したモデルも検証に失敗すれば推論に渡さない。ブラウザによる保存領域の削除時は再取得される。Transformers.js側の別キャッシュは無効化し、モデルを二重保存しない。
## 検証
`node verify-editor.cjs <@napi-rs/canvasモジュールの絶対パス>`で、既知のマスクを使った編集状態とPNG出力を検証する。実モデルの推論を代替するテストではない。Actionsでは`@napi-rs/canvas@0.1.100`を使用する。

`node verify-cache.cjs <hash-wasmのxxhash64 CommonJSモジュールの絶対パス>`で、GitHub Pagesのサブパス解決、本番と同じ50MB分割・復元、キャッシュ再利用、破損修復、不正ダウンロード拒否を確認する。テストはService Workerのストレージとfetchをメモリ上で置き換え、実際のmodel-cache.jsを実行する。Actions内でも同じテストを実行する。
編集の検証では、実際のapp.jsに対してクリック・ドラッグ・タッチ・ペンのイベントを渡し、一筆を一つの選択として扱うこと、指を離すまで推論しないこと、途中の点を含む座標のサンプリング、長い線の点数制限、操作中断、画像切り替え、線単位の取り消しを確認する。既知のマスク入力による合成、透過PNGのアルファ・寸法、切り詰め、処理途中の保存抑止、取り消し後の古い応答の無視も確認する。実モデルによる切り抜き精度は、HTTPSの公開サイトで別途確認する。
## 配布物
個人の写真、デバッグ用画像、サンプル画像の読み込み機能は含めない。添付coi-serviceworkerのMIT表記を保持。ユーザー画像をサーバーへ保存する機能はない。
